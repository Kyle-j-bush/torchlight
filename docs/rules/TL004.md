# TL004: Single-partition write after repartition(1)

Available in v0.4.0+. Warning; no automatic fix.

## Detection and evidence

A known Spark DataFrame is explicitly repartitioned to **literal integer 1**,
and that result reaches a recognized V1 or V2 terminal write without a recognized
intervening shuffle restoring unknown/multiple partitions. The warning is at the
**write**, with the Spark origin and repartition's line/cell as evidence.

```python
from pyspark.sql import SparkSession

events = SparkSession.builder.getOrCreate().table("events")
export = events.repartition(numPartitions=1)
export.write.mode("overwrite").parquet("export")  # TL004
```

Aliases, known partition-preserving transformations, writer options, and notebook
document-order state preserve the fact. A dynamic partition count, a column-only
repartition, an unknown receiver, or `repartition(1)` **without a terminal write**
does not trigger this rule. `repartitionByRange` does not establish new evidence.

## Non-triggering examples

```python
from pyspark.sql import DataFrame


def export(events: DataFrame):
    events.repartition(8).write.parquet("parallel")
    events.repartition(1)  # No terminal write.
    events.repartition(1).repartition(8).write.parquet("restored")
```

## Review and suppression

**Question:** Is one output partition intentional for a small export, or is it
unnecessarily restricting a large write? A literal row limit does not decide
this question. One partition does not guarantee exactly one file: partitioned
outputs, write options, and data sources affect file layout.

```python
export.write.csv("export")  # torchlight: ignore[TL004] -- reviewed small export
```

Suppress the write, not an earlier repartition assignment. Do not automatically
substitute `coalesce(1)`; coalesce and repartition have different execution
behavior. If coalesce provenance also reaches the write, TL002 takes precedence
and Torchlight does not emit duplicate single-partition warnings.

## Semantics and limitations

The [Spark repartition API](https://spark.apache.org/docs/latest/api/python/reference/pyspark.sql/api/pyspark.sql.DataFrame.repartition.html)
documents the target partition count (available since Spark 1.3, Connect support
since 3.4). This is not runtime plan verification, a file-count promise, or a
Spark/vendor-version compatibility guarantee. Unknown APIs and ambiguous paths
can discard evidence. Independently labeled real-world precision is not yet
measured. [All rules](README.md).
