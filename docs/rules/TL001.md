# TL001: Potential driver-memory risk

## Detection and evidence

A `.collect()` or `.toPandas()` call on a **known Spark DataFrame** without a
recognized row bound. Evidence includes the Spark origin and absence of a known
bound. Import aliases, builders, annotations, and supported transformations can
establish identity. An unrelated object's `.collect()` is not enough.

```python
from pyspark.sql import SparkSession

df = SparkSession.builder.getOrCreate().table("events")
rows = df.collect()  # TL001
```

## Non-triggering example

```python
from pyspark.sql import SparkSession

df = SparkSession.builder.getOrCreate().table("events")
preview = df.limit(10).collect()
```

Literal bounds can be invalidated by later expanding transformations. Unknown
helper-returned DataFrames and dynamic limits are not fully understood. A known
bound, even a large one, does not prove memory safety.

## Review and suppression

**Question:** Is materializing the full result in driver memory necessary, and
has its memory footprint been verified? Keep work distributed where appropriate.
Do not add a limit unless partial results preserve the intended semantics.

```python
rows = df.collect()  # torchlight: ignore[TL001] -- verified small lookup result
```

## Version and policy notes

Warning; no autofix. There is no Spark-version filter or independently measured
confidence score. Spark API availability and behavior must be checked against
the deployed distribution. [All rules](README.md).
