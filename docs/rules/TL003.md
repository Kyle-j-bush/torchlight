# TL003: Loop-carried withColumn() can grow the logical plan

## Detection and evidence

A known Spark DataFrame is repeatedly assigned through `.withColumn()` in a
possibly repeated loop, carrying the same DataFrame's plan from iteration to
iteration. Evidence includes its origin and loop-carried assignment context.
Merely calling `.withColumn()` somewhere inside a loop is not enough.

```python
from pyspark.sql import SparkSession

df = SparkSession.builder.getOrCreate().table("events")
for name in names:
    df = df.withColumn(name, expression)  # TL003
```

## Non-triggering example

```python
from pyspark.sql import SparkSession

spark = SparkSession.builder.getOrCreate()
for name in names:
    fresh = spark.table("events")
    fresh = fresh.withColumn(name, expression)
```

Independent projections, fresh DataFrames, and recognized single-iteration loops
do not establish repeated plan growth. Dynamic loop counts and complex control
flow remain approximate; this is not a planning-time cost model.

## Review and suppression

**Question:** Can expressions be constructed together without changing column
dependencies? `select()` or, where available, `withColumns()` may help, but blindly
combining dependent expressions can change results.

```python
for name in names:
    df = df.withColumn(
        name, expression
    )  # torchlight: ignore[TL003] -- small dependent projection chain
```

## Version and policy notes

Warning; no autofix. `withColumns()` was introduced in Spark 3.3; check availability
in your deployed distribution before using that alternative. Torchlight does not
yet gate recommendations on a target Spark version. There is no independently
measured confidence tier. [All rules](README.md).
