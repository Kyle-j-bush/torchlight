# TL005: Eager consumption of a Spark local iterator

Available in v0.6.0+. Warning; no automatic fix.

```python
from pyspark.sql import DataFrame


def export(events: DataFrame):
    return list(events.toLocalIterator())  # TL005
```

The built-in `list()` or `tuple()` consumes a known Spark DataFrame iterator and
retains its rows locally. This defeats streaming's memory advantage. A normal
`toLocalIterator()` is **not** `collect()`: Spark documents memory consumption up
to the largest partition (two with prefetch in classic Spark; prefetch does not
take effect in Connect). TL005 does not report ordinary streaming iteration.

```python
def stream(events: DataFrame):
    for row in events.toLocalIterator():  # no TL005
        consume(row)


def preview(events: DataFrame):
    return tuple(events.limit(100).toLocalIterator())  # no TL005
```

## Required evidence

- Proven Spark DataFrame receiver, using existing import/annotation/session facts.
- `toLocalIterator()` provenance, directly or through a local alias.
- Proven built-in `list`/`tuple` consumer, or a known alias of one. Rebinding,
  parameter/local shadowing, unknown calls, and opaque notebook cells lose proof.
- No recognized explicit row bound. Expanding operations after a limit remove
  that bound as with TL001. A bound, even a large one, is not proof of safety.

The warning is located at the outer container call. Suppress that call with a
reason only after reviewing the intended full local result:

```python
rows = list(
    events.toLocalIterator()
)  # torchlight: ignore[TL005] -- reviewed small export
```

## Limits and review

This rule does not model iterator exhaustion, runtime row sizes, or memory
budgets. It does not currently recognize comprehensions, `sorted`, `set`,
`deque`, custom consumers, or explicit `builtins.list` module imports. A Python
loop can still retain every row; absence of TL005 is not proof of streaming-safe
behavior. No automatic rewrite can preserve every consumer's requirements.

Receiver inference remains definition-site, not interprocedural. Runtime
monkey-patching of built-ins or Spark methods is not modeled. Spark-version
targeting is not needed for this warning; see the
[version assessment](../development/spark-versions.md) for source evidence.
